# 機能仕様

## テンプレート

保存されるノートの形はすべてテンプレートで決まります。テンプレートは設定画面の
サイドバーから追加・複製・削除でき、次の項目を持ちます。

| 項目 | 説明 |
| --- | --- |
| テンプレート名 | サイドバーとポップアップの選択肢に出る名前 |
| 自動選択の条件 | 1 行 1 パターン。前方一致か `/正規表現/i`。開いている URL に一致したテンプレートが自動で選ばれます |
| 動作 | 新規作成 / 末尾に追加 / 先頭に追加 / 上書き |
| ノート名 | 変数が使えます。ファイル名に使えない文字は自動で置き換えます |
| ノートの保存先 | Vault 内のフォルダ |
| PDF と画像の保存先 | 空欄ならノートと同じ場所 |
| Vault | このテンプレートで使う Vault |
| プロパティ | フロントマターになる項目の並び |
| ノート本文 | フロントマターの下に入る Markdown |

テンプレートは JSON としてエクスポート・インポートできます（「その他」メニュー）。

### ノート名の整形

ノート名は変数を展開したあと、ファイル名として使える形に整えられます。

- `\ / : * ? " < > | # ^ [ ]` は空白に置き換え、連続する空白は 1 個にまとめます
- **UTF-8 で 240 バイト**を超える場合は切り詰めます（日本語で約 80 文字）。
  単語の途中で切れないよう、直前の空白まで戻します

Speaker Deck のタイトルは `日本語タイトル / English title / イベント名` のように
`/` で区切られていることが多く、そのままだと `/` が空白になって 1 続きの文に見えます。
片方だけを使いたい場合はフィルタで切り出してください。

```
{{date}}_{{title|split:"/"|first|trim}}   日本語タイトルだけ
{{title|split:"/"|last|trim}}              最後の要素だけ
{{title|slice:0,40}}                       先頭 40 文字だけ
```

### 動作とノートの関係

| 動作 | Vault へ直接書き込み | ダウンロード + URI |
| --- | --- | --- |
| 新規作成 | 同名ノートがあれば `ノート名 1.md` として作成 | `obsidian://new` |
| 末尾に追加 | 既存ノートを読んで末尾に連結 | `&append=true` |
| 先頭に追加 | 既存ノートを読んで先頭に連結 | `&prepend=true` |
| 上書き | 既存ノートを置き換え | `&overwrite=true` |

## プロパティ

プロパティは**名前・値・型**の 3 つで決まります。名前と値はテンプレートごと、
型は名前ごとに拡張全体で共通です（Obsidian のプロパティと同じ考え方）。

型はフロントマターの書き方を決めます。

| 型 | 出力 |
| --- | --- |
| テキスト | `key: "値"` |
| リスト | `key:` の下に `- "値"` を並べる。カンマ区切りで複数に分かれます |
| 数値 | `key: 42`（数字以外を除去） |
| チェックボックス | `key: true` / `false` |
| 日付・日時 | `key: 2026-08-08`（引用符なし） |

型の一覧は設定画面の「プロパティ」で編集できます。ここでは次のこともできます。

- **既定値の設定**: テンプレートでそのプロパティを追加したとき、値欄に自動で入ります
- **types.json の読み書き**: Vault の `.obsidian/types.json` を読み込めば Obsidian 側と型を揃えられます
- **未使用プロパティの削除**: どのテンプレートからも使われていない型定義をまとめて消します

テンプレート編集画面では、プロパティ行の左のアイコンから型を変え、ドラッグで並べ替え、
ゴミ箱で削除できます。名前を入力すると既存のプロパティ型が補完され、型と既定値が引き継がれます。

## 変数

テンプレートのノート名・保存先・プロパティ値・本文で `{{変数名}}` として使えます。

| 変数 | 内容 |
| --- | --- |
| `{{title}}` | スライドのタイトル |
| `{{author}}` | 発表者名 |
| `{{url}}` / `{{domain}}` | スライドの URL / ドメイン |
| `{{description}}` | 概要欄のテキスト |
| `{{published}}` | 公開日 |
| `{{date}}` / `{{time}}` | 今日の日付 / 現在の日時（ISO 8601） |
| `{{pdfUrl}}` / `{{pdfLink}}` | PDF の URL / Vault 内の PDF への埋め込みリンク |
| `{{deckId}}` / `{{thumbnail}}` | Speaker Deck の内部 ID / サムネイル URL |
| `{{noteName}}` | 確定したノート名 |
| `{{slideCount}}` / `{{ocrCount}}` / `{{textCount}}` | ページ数 / OCR したページ数 / テキスト抽出できたページ数 |
| `{{slides}}` / `{{content}}` | 全スライドの Markdown（埋め込み + 抽出テキスト） |
| `{{allText}}` / `{{firstText}}` | 全ページの抽出テキスト / 1 ページ目の抽出テキスト |

解析前は `{{slides}}` などページ由来の変数が空になります。解析すると本文が組み立て直されます
（手で編集した欄は上書きしません）。

## フィルタ

`{{変数|フィルタ}}` の形で値を加工できます。`|` でいくつでもつなげられます。

```
{{author|split:", "|wikilink|join}}   →  [[著者A]],[[著者B]]
{{published|date:"YYYY/MM/DD"}}       →  2026/08/08
{{description|callout:("quote","概要",true)}}
```

| 分類 | フィルタ |
| --- | --- |
| 日付 | `date` |
| 文字列 | `upper` `lower` `title` `capitalize` `trim` `camel` `pascal` `kebab` `snake` `uncamel` `safe_name` `replace` |
| 整形 | `blockquote` `callout` `list` `wikilink` `link` `image` |
| 数値 | `calc` `round` `length` |
| 配列 | `split` `join` `first` `last` `nth` `slice` `unique` |

一覧と説明は設定画面の「変数とフィルタ」にもあります（クリックでコピーできます）。
`markdown` や `table` のように HTML・オブジェクトを前提とするフィルタは、この拡張が扱うのが
PDF から取り出した平文だけであるため実装していません。テンプレートに書くと警告が出ます。

## 生成される Markdown

```markdown
---
title: "スライドタイトル"
author:
  - "著者名"
source: "https://speakerdeck.com/user/slug"
published: 2026-08-08
created: 2026-09-05
description: "概要欄のテキスト"
pdf: "https://files.speakerdeck.com/.../deck.pdf"
tags:
  - "slide"
  - "speakerdeck"
---

# スライドタイトル

## 概要
概要欄テキスト

---

## スライド一覧

### Slide 1
![[スライドタイトル/slide-001.webp]]

> [!quote]- 📄 抽出テキスト / OCR
> 1ページ目のテキスト
>
> 空行があっても折りたたみの中に収まります

---
```

## 抽出テキストの表示形式

設定画面の「出力 → 抽出テキストの表示」で選べます。

| 値 | 出力 |
| --- | --- |
| **折りたたみコールアウト**（既定） | `> [!quote]- 📄 抽出テキスト / OCR` |
| `<details>` タグ | `<details><summary>…</summary><pre>…</pre></details>` |
| 折りたたまない | テキストをそのまま |

> **なぜ既定が `<details>` ではないか**
> CommonMark では `<details>` で始まる HTML ブロックは **最初の空行で終了**します。
> OCR の結果には空行が普通に含まれるため、`<details>` に素の Markdown を入れると
> 途中から先の本文がトグルの外へこぼれ出ます。
> コールアウトは全行が `>` で始まるためこの問題が原理的に起きません。
>
> `<details>` を選んだ場合は、空行を潰したうえで HTML エスケープして `<pre>` に入れるので、
> こぼれ出しは起きません（代わりに中身は等幅表示になります）。

## スライドの埋め込み形式

設定画面の「出力 → スライドの埋め込み」で 2 通りから選べます。

### 画像（既定）

各ページを WebP 画像として書き出し、`![[{ノート名}/slide-001.webp]]` で埋め込みます。

- **静止画なので PDF ビューアの UI（`1/35` のページ送り）が出ません**
- 埋め込みごとに PDF を読み込まないため、ページ数が多いノートでも軽い
- OCR 用にどのみち各ページを canvas へ描画しているので、**追加コストはほぼゼロ**
- デッキ名のサブフォルダにまとめて置くので Vault が散らかりません

### PDF のページ指定

`![[{ノート名}.pdf#page=N]]` を使う方式です。ファイルが PDF 1 個で済む代わりに、
**Obsidian は埋め込みごとに PDF ビューアを開く**ため、各スライドに `1/35` のようなページ送り UI が付き、
ページ数ぶんビューアが並ぶことになります。

| | 画像 | PDF ページ指定 |
| --- | --- | --- |
| 見た目 | 静止画のみ | PDF ビューア（`N/35` 表示つき） |
| ファイル数 | ページ数ぶん + PDF | PDF 1 個 |
| 容量 | 1600px WebP で 1 枚 100〜200KB 程度 | PDF のサイズのみ |
| 表示の軽さ | 軽い | ページ数に比例して重い |

大きすぎる場合は「レンダリング幅」か「画像の品質」を下げてください。
`![[...pdf#page=N]]` を使う場合は、**PDF が Vault 内に置かれている**必要があります。

## 保存方法

### A. Vault に直接書き込み（既定・推奨）

File System Access API を使い、**ノート・画像・PDF を Vault の中へ直接書き込みます**。
ダウンロードフォルダは一切経由しません。

初回だけ設定画面の「一般 → Vault フォルダ」で **Vault のルートフォルダを指定**してください。
選んだフォルダのハンドルは IndexedDB に保存されるので、次回以降は選び直し不要です。

- 保存先に指定したフォルダは、**無ければ自動的に作成されます**
- Vault 名は選んだフォルダ名から自動で登録されます（保存後にノートを開くのに使います）
- クリップボードコピーや `obsidian://` の長さ制限は関係ありません
- ブラウザ再起動後は書き込み許可の再確認が入ることがあります（保存時に 1 クリック）

### B. ダウンロード + `obsidian://` URI

File System Access を使いたくない場合の方式です。
`chrome.downloads` API は**ダウンロードフォルダ配下にしか保存できない**（絶対パス・`..` は不可）ため、
PDF と画像はいったんダウンロードフォルダに落ちます。Vault へ入れるには次のいずれかが必要です。

- `chrome://settings/downloads` でダウンロード先を Vault の添付フォルダに変える
- 保存後に手動で移動する
- `ln -s ~/Obsidian/MyVault/attachments ~/Downloads/VaultAttachments` のようなシンボリックリンクを張る

**URI 長制限への対策**: エンコード後の URI が 8,000 文字を超える場合は `content=` を諦め、
代わりに **`clipboard=true`** を付けて送出します。Obsidian 側がクリップボードの中身を本文として
取り込むため、**ノートの長さに関係なく全文が渡ります**。

> 日本語は 1 文字が `%E4%BA%8B` のように 9 文字へ膨らむため、見た目 1 万文字のノートでも
> URI は 6〜7 万文字になります。長いスライドではほぼ常にクリップボード経由になります。

#### 保存先パスの制約（重要）

`obsidian://` は **Vault 内に存在しないフォルダにはノートを作成できません**（黙って失敗します）。
この方式では、テンプレートの「ノートの保存先」に **既に Vault 内にあるフォルダ**だけを指定してください。

## 設定項目

### 一般

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| 保存方法 | Vault に直接書き込み | 上記 A / B |
| Vault フォルダ | 未選択 | 直接書き込み先の Vault ルート |
| Vault 名 | （空） | `obsidian://` で使う Vault 名。先頭が既定 |
| 保存ボタンの既定動作 | Obsidian に追加 | ファイル保存 / クリップボードコピーも選べる |
| 保存後に Obsidian でノートを開く | ON | 直接書き込み時のみ |
| Obsidian 連携方式 | `obsidian://new` | URI 方式のみ |
| `.md` ファイルも保存 | ON | URI 方式のみ（バックアップ） |
| クリップボードにコピー | ON | |

### 解析

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| OCR する | ON | テキストが取れないページを Tesseract.js に回す |
| OCR 判定しきい値 | 20 文字 | 抽出文字数がこれ未満なら OCR にフォールバック |
| OCR 言語 | 日本語 + 英語 | `jpn+eng` / `jpn` / `eng` |
| レンダリング幅 | 1600 px | 大きいほど精度が上がり、遅くなる |
| 最大ページ数 | 0（全部） | 動作確認時に数ページだけ試したいとき用 |

### 出力

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| スライドの埋め込み | 画像 | 画像 / PDF のページ指定 |
| 画像の品質 | 0.82 | WebP の圧縮品質 |
| 抽出テキストの表示 | 折りたたみコールアウト | |
| PDF も保存する | ON | ページ埋め込みに必要 |
