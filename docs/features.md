# 機能仕様

## 生成される Markdown

```markdown
---
title: "スライドタイトル"
author: "著者名"
source: "https://speakerdeck.com/user/slug"
date: "2026-08-08"
tags: [slide, speakerdeck]
---

# スライドタイトル

## 概要
概要欄テキスト

---

## スライド一覧

### Slide 1
![[スライドタイトル/slide-001.webp]]

> [!quote]- 📄 抽出テキスト / OCR
> 1ページ目のテキスト
>
> 空行があっても折りたたみの中に収まります

---
```

## 抽出テキストの表示形式

⚙ 設定の「抽出テキストの表示」で選べます。

| 値 | 出力 |
| --- | --- |
| **折りたたみコールアウト**（既定） | `> [!quote]- 📄 抽出テキスト / OCR` |
| `<details>` タグ | `<details><summary>…</summary><pre>…</pre></details>` |
| 折りたたまない | テキストをそのまま |

> **なぜ既定が `<details>` ではないか**
> CommonMark では `<details>` で始まる HTML ブロックは **最初の空行で終了**します。
> OCR の結果には空行が普通に含まれるため、`<details>` に素の Markdown を入れると
> 途中から先の本文がトグルの外へこぼれ出ます。
> コールアウトは全行が `>` で始まるためこの問題が原理的に起きません。
>
> `<details>` を選んだ場合は、空行を潰したうえで HTML エスケープして `<pre>` に入れるので、
> こぼれ出しは起きません（代わりに中身は等幅表示になります）。

## スライドの埋め込み形式

⚙ 設定の「スライドの埋め込み」で 2 通りから選べます。

### 画像（既定）

各ページを WebP 画像として書き出し、`![[{ノート名}/slide-001.webp]]` で埋め込みます。

```markdown
### Slide 1
![[事業価値と Engineering/slide-001.webp]]
```

- **静止画なので PDF ビューアの UI（`1/35` のページ送り）が出ません**
- 埋め込みごとに PDF を読み込まないため、ページ数が多いノートでも軽い
- OCR 用にどのみち各ページを canvas へ描画しているので、**追加コストはほぼゼロ**
- デッキ名のサブフォルダにまとめて置くので Vault が散らかりません

### PDF のページ指定

`![[{ノート名}.pdf#page=N]]` を使う方式です。ファイルが PDF 1 個で済む代わりに、
**Obsidian は埋め込みごとに PDF ビューアを開く**ため、各スライドに `1/35` のようなページ送り UI が付き、
ページ数ぶんビューアが並ぶことになります。

| | 画像 | PDF ページ指定 |
| --- | --- | --- |
| 見た目 | 静止画のみ | PDF ビューア（`N/35` 表示つき） |
| ファイル数 | ページ数ぶん + PDF | PDF 1 個 |
| 容量 | 1600px WebP で 1 枚 100〜200KB 程度 | PDF のサイズのみ |
| 表示の軽さ | 軽い | ページ数に比例して重い |

書き出した画像の合計サイズはポップアップのログに出ます。大きすぎる場合は
「レンダリング幅」を下げてください（OCR 精度と共通の設定です）。

`![[...pdf#page=N]]` を使う場合は、**PDF が Vault 内に置かれている**必要があります（下記）。

## 出力方式

### A. Vault に直接書き込み（既定・推奨）

File System Access API を使い、**PDF とノートを Vault の中へ直接書き込みます**。
ダウンロードフォルダは一切経由しません。

初回だけ **「Vault フォルダ」の「選択…」から Vault のルートフォルダを指定**してください。
選んだフォルダのハンドルは IndexedDB に保存されるので、次回以降は選び直し不要です。

- 「ノート保存先」「PDF 保存先」に指定したフォルダは、**無ければ自動的に作成されます**
- Vault 名は選んだフォルダ名から自動で入ります（「保存後に Obsidian でノートを開く」に使用）
- クリップボードコピーや `obsidian://` の長さ制限は関係ありません

> **ポップアップではなくタブで選択します**
> Chrome ではポップアップからフォルダ選択ダイアログを開くとポップアップ自体が閉じてしまうため、
> 「選択…」を押すと自動でタブに切り替わります。そのタブで選び直してください。
> ブラウザ再起動後は書き込み許可の再確認が入ることがあります（「Obsidian に追加」時に1クリック）。

### B. ダウンロード + `obsidian://` URI

File System Access を使いたくない場合の従来方式です。
`chrome.downloads` API は**ダウンロードフォルダ配下にしか保存できない**（絶対パス・`..` は不可）ため、
PDF はいったんダウンロードフォルダに落ちます。Vault へ入れるには次のいずれかが必要です。

- `chrome://settings/downloads` でダウンロード先を Vault の添付フォルダに変える
- 保存後に手動で移動する
- `ln -s ~/Obsidian/MyVault/attachments ~/Downloads/VaultAttachments` のようなシンボリックリンクを張る

## Obsidian への送出方式

| 方式 | URI | 備考 |
| --- | --- | --- |
| 標準 | `obsidian://new?vault=…&file=…&content=…` | 追加プラグイン不要 |
| Advanced URI | `obsidian://advanced-uri?vault=…&filepath=…&data=…&mode=new` | [Advanced URI](https://github.com/Vinzent03/obsidian-advanced-uri) プラグインが必要 |
| 送出しない | — | クリップボード / `.md` 保存のみ |

**URI 長制限への対策**: 生成した Markdown は毎回クリップボードにもコピーされます。
エンコード後の URI が 8,000 文字を超える場合は `content=` を諦め、代わりに **`clipboard=true`** を付けて送出します。
Obsidian 側がクリップボードの中身を本文として取り込むため、**ノートの長さに関係なく全文が渡ります**。

> 日本語は 1 文字が `%E4%BA%8B` のように 9 文字へ膨らむため、見た目 1 万文字のノートでも
> URI は 6〜7 万文字になります。長いスライドではほぼ常にクリップボード経由になります。

### 保存先パスの制約（重要）

`obsidian://` は **Vault 内に存在しないフォルダにはノートを作成できません**（黙って失敗します）。
「保存先パス」には **既に Vault 内にあるフォルダ**だけを指定してください。既定は空欄（Vault 直下）です。
指定した場合はポップアップのログにも注意書きが出ます。

## 設定項目

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| OCR する | ON | テキストが取れないページを Tesseract.js に回す |
| OCR 判定しきい値 | 20 文字 | 抽出文字数がこれ未満なら OCR にフォールバック |
| OCR 言語 | 日本語 + 英語 | `jpn+eng` / `jpn` / `eng` |
| OCR レンダリング幅 | 1600 px | 大きいほど精度が上がり、遅くなる |
| 最大ページ数 | 0（全部） | 動作確認時に数ページだけ試したいとき用 |
| PDF も保存する | ON | ページ埋め込みに必要 |
| 保存後に Obsidian でノートを開く | ON | 直接書き込み時のみ |
| Obsidian 連携方式 | `obsidian://new` | URI 方式のみ |
| `.md` ファイルも保存 | ON | URI 方式のみ（バックアップ） |
| クリップボードにコピー | ON | |
